# 本批资料的查看和重排操作

适用范围：本地23级原表316份学生资料，其中301人参加预答辩及正式答辩，15人因原表明确备注不参加本次答辩。15人保留资料、备注和空白校区，不补校区，不添加参与环节。当前修正版两阶段各50组；组数是本次生成结果，验收依据是参排名单及业务规则。

## 直接查看已生成结果

1. 在资源管理器打开项目下的 `test-data/交付结果/2026-10-23/`。
2. 打开 `答辩排期总表.xlsx`：查看两阶段排期、学生查询、教师日程及待确认事项；“不参加本次答辩”页列出15人的原始原因。
3. 需要在系统内查看或调整，双击 `打开排期系统.cmd`，保持终端开启，用原有本地账号登录。此入口指定该目录的 `本次排期.sqlite3`，不是日常业务库。
4. 分别查看预答辩、正式答辩：各301人、50组，当前版本为草稿。若看到316人参排，先核对启动入口和当前版本，不要给15人补校区。
5. 查看 Word 时使用 `预答辩排期建议.docx`、`正式答辩排期建议.docx`。内容已核对301个学号；本轮视觉分页尚未完成，打印前需检查分页。

前提是项目已有 `.venv` 及构建后的 `dist/index.html`。入口会检查这些文件，缺少时会停止并说明，不会自动安装依赖或改用其他数据库。关闭对应终端即可停止本次服务。

## 用同一批原文件重新生成

1. 双击同目录的 `重新导入并生成.cmd`，保持窗口开启。
2. 脚本检查原学生表、指定组长秘书表及四份春季课表，然后在日常业务库的独立副本中重新导入和生成。
3. 导入预期为301人参排、15人不参排；不需要手动给15人补校区。脚本固定本批春季配置，人数改变时会停止，不能直接用来处理其他年级。
4. 成功后自动打开新的 `test-data/_diagnostics/delivery-20261023-…/` 目录。其中 `pre.xlsx`、`pre.docx` 为预答辩，`formal.xlsx`、`formal.docx` 为正式答辩；`summary.json` 记录人数、冲突和导出检查。
5. 使用新打开目录中的文件核对本次结果。此操作不会覆盖交付目录的总表、Word或 `本次排期.sqlite3`；再次点击“打开排期系统”仍打开已交付的修正版。新生成目录保留独立 `isolated.sqlite3` 供后续处理，不自动替换当前业务库。

当前设置为预答辩2026-04-01至04-15、正式2026-05-06至05-22，四份课表第一周周一为2026-03-02。8间教室使用历史名称，按工作日可用、至少14座测算，借用尚未确认。原始文件和日常业务库保持不变。

仅检查入口依赖、不启动服务也不生成，可在项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "test-data/交付结果/2026-10-23/open-schedule.ps1" -CheckOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "test-data/交付结果/2026-10-23/regenerate.ps1" -CheckOnly
```

## 从网页导入并操作

1. 学生管理 → 批量导入学生与导师，选择指定组长秘书表和原学生表。
2. 勾选预答辩、正式答辩；空白校区补充选项保持空白，点击“检查批量资料”。
3. 核对301位参排、15位不参排及原因；教师为43位软件学院教师和68位参排所需外院导师。确认导入后，已有15人的错误参与环节会清空。
4. 导入四份春季课表，核对教室资源，并分别保存两个阶段的安排要求。
5. 分组与发布 → 联合生成预答辩与正式答辩；返回草稿后逐阶段核对301人各出现一次、15人均不出现、硬冲突为0。
6. 无硬冲突草稿可先导出。落实实际日期、教室借用及人员可用性后再校验发布；不能把拟用教室视为已确认。

具体文件及参数见[教师快速上手](教师快速上手.md)。这仍是网页分步操作；固定批次脚本不代表网页已实现任意资料一次上传即完成全部准备。

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 本环节人数0，总资料已有316人 | 核对启动的数据库、当前环节和参排预览；仅为确实参排的人补充环节 |
| 15人出现在“未设置参与环节”中 | 确认使用已更新源码及前端构建，重新导入并核对明确备注；当前版本应显示“不参加本次答辩” |
| 其他参排学生校区空白、备注不明确 | 核对来源后补充，不能仅凭空白校区排除 |
| 批量设置环节被拒绝 | 所选含明确不参排者；如确实恢复参加，先核对并更正备注和校区，再设置环节 |
| 重新生成失败 | 保留窗口错误内容；失败不会覆盖已交付结果，也不会自动打开旧的生成目录 |

当前结果及验证限制见[301人排期交付](../releases/排期结果交付-2026-10-23.md)。旧316人全部参排报告只作历史记录。
